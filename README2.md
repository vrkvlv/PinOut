# PinOut

**Простий довідник по Arduino, мікроконтролерах і модулях + ідеї нескладних проєктів з покроковими інструкціями.**

## Про що сайт

**PinOut** - гайд-помічник, який допоможе розібратися, що робити з вашими новими Arduino і набором датчиків.

- **Розкаже про компоненти:** що таке Arduino Nano, ESP32, датчик DHT22, дисплей OLED і не тільки.
- **Допоможе з проєктами:** надасть нескладні ідеї, для кожної випише список потрібних матеріалів і покрокову інструкцію з кодом.
- **Збереже ваш прогрес:** можна зберігати свої проєкти й відмічати, які кроки вже зроблено.

## Сторінки

- **Каталог компонентів** - усі компоненти.
- **Компонент** - опис, де застосовується, характеристики, проєкти з цим компонентом.
- **Виробники** - список виробників.
- **Категорії** - мікроконтролери, датчики, дисплеї тощо.
- **Проєкти** - список проєктів.
- **Проєкт** - ідея, потрібні матеріали, покрокова інструкція.
- **Вхід/Реєстрація** - звичайні форми.
- **Профіль** - мої дані та мої проєкти.
- **Про нас** - контакти та інформація про сайт.

Адміністратор може додавати, редагувати й видаляти компоненти, виробників, категорії та проєкти.

## Як запустити проєкт

Потрібен Python 3.12 або новіший. Усі команди виконуються в папці з `manage.py`.

1. Створити й активувати віртуальне середовище:

   ```
   python -m venv .venv

   # Windows
   .venv\Scripts\activate
   # Linux / macOS
   source .venv/bin/activate
   ```

2. Встановити залежності:

   ```
   python -m pip install -r requirements.txt
   ```

3. Створити базу даних (застосувати міграції):

   ```
   python manage.py migrate
   ```

4. (Необов'язково) Створити адміністратора для `/admin/`:

   ```
   python manage.py createsuperuser
   ```

5. Запустити сервер:

   ```
   python manage.py runserver
   ```

Бекенд працює на **http://127.0.0.1:8000**, API - на **http://127.0.0.1:8000/api/**, адмінка - на **http://127.0.0.1:8000/admin/**.

Фронтенд лежить в окремому репозиторії і працює на порту **5500**. Для нього на бекенді налаштовано CORS (`CORS_ALLOWED_ORIGINS` у `config/settings.py`).

Postman-колекція з усіма запитами лежить у папці `postman/`. Базова адреса винесена у змінну `{{base_url}}`.

## API

Усі запити починаються з `/api/`, дані передаються в **JSON**.

**Коди відповідей:**

- `200` - все окі
- `201` - створено
- `204` - видалено (без тіла)
- `400` - щось не так із даними в запиті
- `404` - не знайдено
- `409` - конфлікт: об'єкт не можна видалити, бо він ще використовується

**Формат помилок** однаковий для всіх ендпоінтів: поле `detail` з поясненням, що сталося (наприклад, «Категорію не знайдено»). Для `400` додатково повертається поле `errors`, де для кожного поля написано, що з ним не так.

> Авторизації поки немає, тому всі запити зараз доступні без входу. Права адміністратора з'являться разом з авторизацією.

### Категорії

| Що робить | Запит | Що передаємо | Що отримуємо |
|---|---|---|---|
| Список | `GET /api/categories/` | — | `200` список категорій |
| Одна категорія | `GET /api/categories/:id/` | — | `200` категорія або `404` |
| Додати | `POST /api/categories/` | категорія | `201` створена категорія або `400` |
| Редагувати | `PATCH /api/categories/:id/` | лише змінені поля | `200` оновлена категорія, `400` або `404` |
| Видалити | `DELETE /api/categories/:id/` | — | `204`, `404` або `409`, якщо в категорії ще є компоненти |

### Виробники

| Що робить | Запит | Що передаємо | Що отримуємо |
|---|---|---|---|
| Список | `GET /api/manufacturers/` | — | `200` список виробників |
| Один виробник | `GET /api/manufacturers/:id/` | — | `200` виробник або `404` |
| Додати | `POST /api/manufacturers/` | виробник | `201` створений виробник або `400` |
| Редагувати | `PATCH /api/manufacturers/:id/` | лише змінені поля | `200` оновлений виробник, `400` або `404` |
| Видалити | `DELETE /api/manufacturers/:id/` | — | `204`, `404` або `409`, якщо у виробника ще є компоненти |

### Компоненти

| Що робить | Запит | Що передаємо | Що отримуємо |
|---|---|---|---|
| Список | `GET /api/components/` | — | `200` список компонентів |
| Один компонент | `GET /api/components/:id/` | — | `200` компонент або `404` |
| Проєкти, де він використовується | `GET /api/components/:id/projects/` | — | `200` список проєктів або `404` |
| Додати | `POST /api/components/` | компонент | `201` створений компонент або `400` |
| Редагувати | `PATCH /api/components/:id/` | лише змінені поля | `200` оновлений компонент, `400` або `404` |
| Видалити | `DELETE /api/components/:id/` | — | `204`, `404` або `409`, якщо компонент використовується в проєктах |

Поля компонента: `name`, `description`, `application`, `specs`, `price`, `image`, `datasheet_url`.

При створенні й редагуванні категорія та виробник передаються як id: `category_id`, `manufacturer_id`. У відповіді вони приходять вкладеними об'єктами `category` і `manufacturer`.

### Проєкти

| Що робить | Запит | Що передаємо | Що отримуємо |
|---|---|---|---|
| Список | `GET /api/projects/` | — | `200` список проєктів |
| Один проєкт | `GET /api/projects/:id/` | — | `200` проєкт або `404` |
| Додати | `POST /api/projects/` | проєкт | `201` створений проєкт або `400` |
| Редагувати | `PATCH /api/projects/:id/` | лише змінені поля | `200` оновлений проєкт, `400` або `404` |
| Видалити | `DELETE /api/projects/:id/` | — | `204` або `404` |

Поля проєкту: `title`, `idea`, `difficulty` (`easy`, `medium` або `hard`), `time`. У відповіді також є список `components` (id, назва, кількість) і список `steps` (номер, назва, текст, картинка, код).

> Через API передаються лише поля самого проєкту (`title`, `idea`, `difficulty`, `time`). Компоненти й кроки API тільки показує, а додаються вони в адмінці на сторінці проєкту. Видалення проєкту видаляє і його кроки.

### Наступний етап: реєстрація, профіль і мої проєкти

Ці ендпоінти ще не реалізовані, вони будуть разом з авторизацією.

| Що робить | Запит | Що передаємо | Що отримуємо |
|---|---|---|---|
| Реєстрація | `POST /api/auth/register` | `{ "email", "password", "name" }` | `201` дані користувача, `400` або `409`, якщо email зайнятий |
| Вхід | `POST /api/auth/login` | `{ "email", "password" }` | `200` або `401` |
| Вихід | `POST /api/auth/logout` | — | `204` |
| Мій профіль | `GET /api/users/me` | — | `200` `{ "id", "email", "name" }` або `401` |
| Змінити профіль | `PATCH /api/users/me` | `{ "name" }` | `200` оновлений профіль, `400` або `401` |
| Мої проєкти | `GET /api/users/me/projects` | — | `200` список |
| Зберегти проєкт собі | `POST /api/users/me/projects` | `{ "projectId": 3 }` | `201`, `404` або `409`, якщо вже збережено |
| Оновити прогрес | `PATCH /api/users/me/projects/:projectId` | `{ "doneStepsCount": 2 }` | `200` оновлений прогрес, `400` або `404` |
| Прибрати проєкт | `DELETE /api/users/me/projects/:projectId` | — | `204` або `404` |

> Сторінка «Про нас» звичайна статична, окремий запит для неї не потрібен.

## База даних

![Схема баз даних](<Знімок екрана 2026-10-14 095709.png>)

**Коротко про зв'язки** (зв'язок іде від «одного» до «багатьох», поле `..._id` лежить на боці «багатьох»):

- **Категорія → Компоненти:** в одній категорії багато компонентів (`components.category_id`).
- **Виробник → Компоненти:** в одного виробника багато компонентів (`components.manufacturer_id`).
- **Проєкти ↔ Компоненти:** проєкт використовує багато компонентів, а компонент буває в багатьох проєктах. Тому є проміжна таблиця `PROJECT_COMPONENTS`, де ще й записано, скільки штук потрібно.
- **Проєкт → Кроки:** у проєкту багато кроків (`steps.project_id`).
- **Користувачі ↔ Проєкти:** через `USER_PROJECTS` видно, які проєкти користувач зберіг собі і скільки кроків уже зробив (буде на етапі авторизації).

**Обмеження:**

- Не можна видалити категорію або виробника, поки в них є компоненти (`409`).
- Не можна видалити компонент, поки він використовується хоча б в одному проєкті (`409`).
